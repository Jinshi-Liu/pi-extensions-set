# discuss-plan

以讨论为核心的工作流：讨论、计划编写与实施授权分离。更新后运行 `/reload`；无需重建会话计划。

## 命令

| 命令 | 行为 |
| --- | --- |
| `/discuss [提示词]` | 停止当前运行，进入只读讨论。有提示词则发送；无提示词仅进入模式，不是开关。 |
| `/plan [提示词]` | 停止当前运行，进入持续计划模式，立即制作或修改当前会话唯一计划。后续普通消息可继续修订计划，不可实施。 |
| `/implement [提示词]` | 按当前模式选择执行路径，见下表。附带要求保留原语言。 |
| `/plan off`、`/discuss off` | 停止并退出工作流，恢复普通工具权限；不主动实施、不删除计划或进度。 |
| `/plan clone` | 显式选择另一个项目计划并复制到本会话；覆盖前确认，重置进度。成功后进入计划模式，不自动改写或实施。 |
| `/plan clear` | 停止后删除当前会话计划，清空对应进度、哈希和任务面板，回只读讨论。不启动模型、不影响其他会话、不回滚代码；重复调用安全。 |
| `/plan help`、`/discuss help` | 查看帮助。 |
| `/todos` | 切换紧凑任务面板。 |
| `/todos show`、`/todos hide` | 显示／隐藏任务面板。 |
| `/todos all` | 打开完整可滚动任务列表（交互终端）。 |
| `/todos help` | 查看任务命令帮助。 |

`/plan` 的保留首词是 `off`、`clone`、`clear`、`help`；`/discuss` 的保留首词是 `off`、`help`，大小写不敏感，子命令不接受额外参数。用 `--` 强制将后文作为提示词，例如 `/plan -- clear the cache design`。提示词保留大小写和换行。

旧版 `make`、`execute`、`steer`、`status` 子命令已移除，没有兼容别名；这些词现在只是普通提示词。不要再使用旧入口切换阶段。

`Ctrl+Alt+P` 在空闲时切换普通／只读讨论，不编写计划或启动实施。忙碌时使用显式命令。启动参数 `--discuss-plan` 进入只读讨论，替代旧启动参数。

## /implement 的执行依据

| 当前模式 | 行为 |
| --- | --- |
| 普通 | 发送普通实施请求；没有明确任务时要求澄清，不搜索旧计划。 |
| 讨论 | 等待停止完成，恢复普通权限，发送 `Implement the plan we just discussed.`。旧计划存在与否不影响此路径，也不额外限制普通工具能力。 |
| 计划 | 等待停止完成，读取本会话保存计划，执行未完成步骤。缺失、空白、无有效任务或全部完成时提示并保持计划模式，不降级成普通实施。 |
| 计划执行 | 不启动第二个执行任务。需要修改时用 `/plan`，需要讨论时用 `/discuss`。 |

计划执行结束不会自动获得计划编辑权限。`/plan` 才返回计划模式；执行中调用也是停止后修订同一文件。重载／恢复则将执行状态恢复为计划待执行状态，不自动发送消息或启动实施。

## 两条使用路径

### 讨论后直接实施

```text
/discuss 如何简化登录流程？
（逐步澄清需求）
/implement
```

无需保存正式计划。即使以前写过计划，只要当前是讨论模式，仍走直接实施路径。

### 讨论—计划—实施—回计划修订

```text
/discuss 重新设计缓存失效机制
/plan 根据讨论制作计划
补充并发失效测试，保持接口兼容
/implement 先运行现有测试
/plan 根据测试结果修订第二步
/implement
```

后续普通消息能持续修改计划，但不能改项目代码。进入 `/discuss` 后会撤销计划写入权限。聊天中的“同意”“开始吧”和问卷答案不会切换模式。

## 计划、权限与进度

计划位于项目 `.pi/plans/<session-id>.md`。绑定依据是程序会话 ID，不是显示名称；重命名会话不改变路径，新会话不继承其他会话的计划。没有文件时，启动和 `/todos` 不自动创建计划。

- 讨论：只读研究及问卷澄清，不写任何文件。
- 计划：只允许通过 `write`／`edit` 修改本会话计划；项目代码、其他会话计划不可修改。
- 计划执行：允许实施，但保存计划受保护。文件被外部修改／删除后撤销当前执行，等待用户检查。
- 普通：恢复正常能力，不叠加计划执行限制。

直接及嵌套工具调用经过同一权限检查。工作流启用时阻止委派，避免子代理绕过会话权限；普通实施不受这一限制。工具检查是工作流边界，不是操作系统沙箱。

停止操作先锁工具，再 `abort`，最后等待 `waitForIdle`；不会把新权限交给旧运行。Pi 1.5.0 的扩展 API 不提供清空消息队列的方法；若停止后仍有排队消息，保持锁定并提示用户清除队列再重试，不在队列未清空时切换权限或开始新实施。Windows 默认可用 `Alt+Q` 将排队消息取回编辑器（其他平台默认 `Alt+Up`），再重试命令。等待失败也保持锁定。

完成进度属于项目、会话及活动分支。修订时按未变化的完整任务文本保留完成状态；改动／新增任务需重新验证。任务格式：

```markdown
## Plan:
1. 实现已确认的修改。
   保留必要细节和验收条件。
2. 验证修改并运行测试。
```

实施中的 `[DONE:n]` 更新会话进度，不自动编辑计划。克隆明确重置进度；取消选择或拒绝覆盖不改变原文件、模式或进度。克隆要求空闲且不在执行状态；先用 `/plan` 或 `/discuss` 停止执行。

旧 `.pi/plan.md` 仅可作为显式克隆来源，不自动采用。`clear` 只操作本会话计划；已实施的项目文件不会回滚。

紧凑面板最多显示五项并跟随首个未完成项；完整列表支持方向键、PageUp/PageDown、Home/End、鼠标滚轮，Esc/Ctrl+C/q 关闭。完整任务文本不截断；重载后面板默认隐藏，进度仍保留。

## 语言

内置提示词、注入指令和固定 UI 文案使用英文；用户提示词保持原文。对话、问卷全部内容、计划正文及任务描述遵循用户语言偏好，不强制英文。`Plan:` 是任务提取标记，不是正文语言要求。

## 迁移与恢复

- 扩展目录由 `plan-mode/` 移为 `discuss-plan/`，旧目录不保留，避免自动发现时重复加载。包清单已更新；若手动配置了旧路径或包资源过滤规则，应改为新路径后 `/reload`。
- 旧 `~/.pi/agent/pi-plan-mode.json` 可保留作配置备份，或自行重命名为 `pi-discuss-plan.json`。包更新不修改个人配置。实现不读取 `defaultPlanTools`，不会据此开放写入或 PowerShell 权限。
- 新持久化类型为 `discuss-plan-workflow`，版本 2；读取兼容旧 `plan-workflow` 版本 1。普通与讨论状态保持原意，计划／旧 make／执行状态恢复成计划待执行；历史版本若已将 make 保存为 discuss，则按已保存的 discuss 恢复，不猜测授权。
- 更旧 `plan-mode` 数据仅用于恢复工具可见性，不采用未知拥有者的计划或进度。旧上下文执行／编写消息被过滤，不因重载启动模型。
- 本会话计划路径、计划正文和任务进度格式不迁移；不扫描其他会话计划。

## 验证

使用本机 Pi 1.5.0 安装依赖，或用 `PI_TEST_INSTALL` 指向其他安装的 `node_modules`，从扩展目录运行：

```text
node workflow-test.mjs
node todos-test.mjs
```

工作流测试实际导入并注册扩展入口，不自动重载当前会话，也不进行真实模型实施或交互终端手工测试。

测试仅在临时项目写计划，覆盖命令解析、旧入口移除、两条实施路径、持续计划权限、执行中修订、两个 off、clear 幂等和隔离、clone 选择／取消／覆盖／重置、语言、进度、恢复／迁移／分支／会话隔离、启动失败、停止／队列／并发／陈旧回调、快照保护和任务面板。任务 UI 测试覆盖 100 项、完整文本、嵌套步骤、滚动、调整尺寸、窄屏、中文和 Unicode。
