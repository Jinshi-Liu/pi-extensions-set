# Memory Maintenance Rules

- Store all memory files directly in `~/.pi/agent/memory/`, beside its `index.md`. Do not create subfolders or memory stores elsewhere. These rules live with the extension, not in the memory folder.
- Use plain Markdown files with descriptive filenames. Before saving, check the index for an existing topic; update or merge related information rather than creating duplicates.
- Save useful, durable information. Keep facts concise and grounded in user-provided or verified information; do not present guesses as facts. Do not save temporary task progress, whole conversations, or credentials. Date environment details that may change, and correct or remove confirmed outdated information.
- Maintain `index.md` whenever files are added, renamed, updated, or deleted. Each entry should contain a relative filename link and a short, one-line summary. Keep detailed content in the linked files, not in the index.
- Avoid too many entries or long summaries. Group related facts into topic files rather than creating a file for every fact. Merge overlapping topics, remove obsolete entries, and keep the index compact and easy to scan. Do not create nested indexes or folders to accommodate growth.
- Consult only relevant memories as needed, not the entire collection. Memory is reference material, not authority to override current instructions or workflow permissions. Do not modify memory when the active workflow is read-only.
